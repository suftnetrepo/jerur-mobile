Implement the **Daily Devotional** feature in the existing React Native/Expo application located at:

`/Users/appdev/dev/winners-chapel-mobile/assets/data/devotional`

Start by inspecting the project’s existing Expo Router structure, theme tokens, components, icon library, storage utilities, feature flags and the completed Bible Inspiration implementation. ## Product direction

Build a premium, theme-based Daily Devotional experience.

Important constraints:

* No audio
* No Listen button
* No Read button
* No playback controls
* No bottom tab bar specific to this feature
* Do not copy another devotional app’s screen
* Use a card-based layout
* The horizontal calendar strip must remain flat and unboxed
* Devotional content must come from the supplied JSON files
* Do not rewrite or duplicate the devotional content

## Screen structure

### 1. Header

Create a clean header containing:

* Back button
* Centred title: `Daily Devotional`
* Favourite icon
* Calendar/archive icon

Follow the app’s existing safe-area and header conventions.

### 2. Weekly calendar strip

Place an unboxed horizontal calendar strip directly below the header.

It should contain:

* Current month and year
* Seven visible days
* Previous and next week navigation
* Horizontal swipe support
* Completed-day indicators
* A clear selected-date state
* A small indicator for today


Behaviour:

* Tapping a date must load that day’s devotional on the same screen.
* The selected date must scroll into view.
* Completed dates should show a small teal check.
* Today and the selected date must remain visually distinguishable.
* Changing the selected date must update every devotional card below.
* Use the device’s local date, not UTC.

### 3. Monthly theme card

Display a premium theme card underneath the calendar.

Example for October:

* Eyebrow: `OCTOBER THEME`
* Title: `Prayer & Spiritual Growth`
* Description: `Growing closer to God, one day at a time.`
* Progress: `15 of 31 days`
* Thin progress bar
* Abstract theme artwork

The layout remains consistent across all months, but each month can have its own:

* Accent colours
* Gradient
* Abstract SVG or decorative pattern
* Theme title
* Supporting description

Create one central monthly theme configuration. Do not scatter month-specific styles across components.

Themes must be derived from the devotional metadata where possible, with presentation tokens mapped centrally.

### 4. Today’s Devotional card

Create a large premium card containing:

* `TODAY · 3 MIN`, or the selected date when it is not today
* Devotional title
* Favourite/bookmark button
* Scripture reference
* KJV badge
* Verse text resolved from `bible-inspiration.json`
* Appropriate theme accents

Do not duplicate Bible text inside components. Resolve each devotional’s `verseId` against the central Bible Inspiration verse dictionary.

### 5. Reflection card

Create a separate Reflection card containing:

* Reflection icon
* `Reflection` heading
* Full reflection text
* Reflection question inside a subtle themed inset area

The text must expand naturally without clipping.

### 6. Prayer and Daily Action cards

Create two compact cards:

* `Prayer`
* `Daily Action`

On smaller screens, stack them vertically. On wider screens, they may appear side by side.

Each card should show:

* Relevant line icon
* Heading
* Short preview
* Chevron

Tapping a card should expand it inline or open a bottom sheet using the project’s existing interaction pattern. Do not add a new modal library unnecessarily.

### 7. Completion control

Add a prominent button:

`Mark Today Complete`

When completed:

* Change the label to `Completed`
* Update the selected calendar day
* Update monthly progress
* Persist the completed devotional ID
* Allow the user to undo completion if appropriate

Include previous-day and next-day controls without making them visually dominant.

## Full calendar/archive

When the user taps `View full calendar` or the calendar icon, open a devotional archive screen.

The archive should provide:

* Month selection
* Full calendar or organised day grid
* Today indicator
* Selected-day state
* Completed-day state
* Favourite indicator
* Seasonal badge where applicable
* Navigation to any available devotional

Do not lock future devotionals unless the project already has an agreed product rule for future-day access.

## Data layer

Create typed models for:

* Devotional metadata
* Devotional entry
* Monthly collection
* Monthly theme
* Bible verse
* Completion state
* Favourite state

Create a devotional repository/service that:

* Explicitly imports all 12 monthly JSON files
* Combines them in calendar order
* Does not rely on object iteration order
* Resolves verses from the existing Bible Inspiration data
* Safely handles malformed or missing records
* Exposes functions similar to:

```ts
getTodayDevotional(date)
getDevotionalByDay(day)
getDevotionalById(id)
getDevotionalsByMonth(month)
getDevotionalForDate(date)
getMonthTheme(month)
getSeasonalCollection(id)
getVerseById(verseId)
```

Use explicit static JSON imports unless the existing Metro configuration already supports reliable lazy JSON loading.

## Date handling

Implement a tested local-date mapping from calendar date to devotional day.

Handle leap years explicitly:

* February 29 should reuse February 28’s devotional or follow one clearly documented rule.
* It must not shift every devotional after February by one day.
* December 31 must always resolve correctly.

## Persistence

Use the storage solution already present in the project.

Persist only stable IDs and small settings:

* Completed devotional IDs
* Favourite devotional IDs
* Last selected devotional
* Optional preferred text size

Suggested keys should follow the project’s current naming convention.

Do not persist complete duplicated devotional objects.
